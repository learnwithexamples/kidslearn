🛡️ Why test?

A test is code that checks your other code. Instead of running your program and eyeballing the output, you write tests that automatically prove it works — and keep proving it as you make changes.

Tests are a safety net. When you add a feature and a test suddenly fails, you've caught a bug before your users do.

✅ The assert statement

The simplest test tool: assert checks that something is true. If it isn't, your program stops and tells you.

def add(a, b): return a + b assert add(2, 3) == 5 # passes silently assert add(0, 0) == 0 # passes print("All tests passed!")

💡 Read it as a promise

assert add(2, 3) == 5 means "I promise add(2, 3) equals 5." If the promise breaks, Python raises an error.

🔴🟢 Test-Driven Development (TDD)

TDD flips the usual order: you write the test first, watch it fail, then write just enough code to pass.

StepColorWhat you do
1. Red🔴Write a failing test for a feature you want.
2. Green🟢Write the simplest code to make it pass.
3. Refactor🔵Clean up the code — tests keep you safe.

🧪 Test the edges

Good tests check normal cases AND tricky edge cases: empty lists, zero, negatives, and the very first/last item.

def biggest(nums): return max(nums) assert biggest([3, 7, 2]) == 7 # normal assert biggest([5]) == 5 # edge: one item assert biggest([-1, -9]) == -1 # edge: negatives

Task 3: Handle the Edge Cases

                    Boss
                

                
Write safe_average(nums) that returns the average of a list — but returns 0 for an empty list (the tricky edge case that crashes careless code). Assert it for [2, 4], [5] and [], then print All edge cases passed!.

                

                    
                    

                        
                        
                        
                        
                    

                    

                

                

                    
def safe_average(nums):
    if len(nums) == 0:
        return 0
    return sum(nums) / len(nums)

assert safe_average([2, 4]) == 3
assert safe_average([5]) == 5
assert safe_average([]) == 0
print("All edge cases passed!")

Task 6: Find the Bug With a Test

                    Medium
                

                
This function is wrong: def biggest(items): return items[0]. First write a test that proves it (assert biggest([3, 9, 2]) == 9 will fail), then fix the function so the test passes. Print Bug squashed 🐞.

                
Bug squashed 🐞

                

                    
                    

                        
                        
                        
                        
                    

                    

                

                

                    
def biggest(items):
    best = items[0]
    for item in items:
        if item > best:
            best = item
    return best

assert biggest([3, 9, 2]) == 9
assert biggest([5]) == 5
assert biggest([-4, -1]) == -1
print("Bug squashed 🐞")

Task 7: TDD: Red, Green, Refactor

def initials(full_name):
    return "".join(part[0].upper() + "." for part in full_name.split())

Task 8: Test That It Fails Properly

                    Tricky
                

                
Good code refuses bad input. Write square_root(n) that raises ValueError for negatives, then test it with try/except: assert the normal case, and confirm the error is raised for −9. Print Errors handled 💥.

                
Errors handled 💥

                

                    
                    

                        
                        
                        
                        
                    

                    

                

                

                    
def square_root(n):
    if n < 0:
        raise ValueError("no square root of a negative number")
    return n ** 0.5

assert square_root(9) == 3.0

try:
    square_root(-9)
    raised = False
except ValueError:
    raised = True

assert raised
print("Errors handled 💥")

Task 9: Boss Level: Test a Whole Class

                    Boss
                

                
Write a ShoppingCart class with add(item, price), total() and remove(item), then write at least six assertions covering an empty cart, one item, several items, removing an item, and removing something that is not there (it should not crash). Print Cart is solid 🛒.

                
Cart is solid 🛒

                

                    
                    

                        
                        
                        
                        
                    

                    

                

                

                    
class ShoppingCart:
    def __init__(self):
        self.items = {}

    def add(self, item, price):
        self.items[item] = price

    def remove(self, item):
        self.items.pop(item, None)

    def total(self):
        return sum(self.items.values())

cart = ShoppingCart()
assert cart.total() == 0
cart.add("apple", 2)
assert cart.total() == 2
cart.add("bread", 3)
assert cart.total() == 5
cart.remove("apple")
assert cart.total() == 3
cart.remove("ghost")
assert cart.total() == 3
assert len(cart.items) == 1
print("Cart is solid 🛒")
